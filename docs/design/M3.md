# M3 — Retrieval quality

All numbers come from `python -m eval.run --offline` and `scripts/measure_gate.py`
on the 160-question gate set and the 125-question retrieval set.

## Changes

1. **Unicode tokenizer.** NFKC, lowercase, `\w`-based words for every script.
   CJK runs become character bigrams. ASCII input takes the old regex path,
   bit-identical. Non-Latin questions are no longer "no searchable terms"
   (known defect #4).
2. **Gate reads the strongest lexical hit among the top-k** instead of the
   fused rank-1 hit (known defect #3). This raised false accepts from 0.188 to
   0.237, all in the borderline band, so the floor was re-measured:
   **RELEVANCE_FLOOR 0.40 → 0.42.**
3. **Follow-ups** (`app/core/query.py`, known defect #5): a deterministic shape
   detector, recomputed gating of the earlier turn, an own-topical-words
   presence check, and a heuristic standalone query (previous question plus the
   follow-up's topical words). Optional LLM rewrite (`QUERY_REWRITE=llm`) is
   called only for follow-ups of in-scope conversations (I5). Optional
   multi-query, cross-encoder reranker and long-context mode change only the
   passages shown to the model, never the gate.
4. **Speed.** NumPy BM25 and cosine over lazily rebuilt arrays (float32
   vectors), an inverted index, and partial top-k selection. BM25 is
   bit-identical to the Python path. Dense differs by float32 rounding, which
   is pinned by a test.
5. **Embedders.** `EMBEDDING_BACKEND=auto` (default): sentence-transformers if
   installed (`EMBEDDING_MODEL`, default `BAAI/bge-small-en-v1.5`), hashing
   otherwise. The cache signature now includes the model name. BGE and E5
   query/passage prefixes are applied.
6. **Calibrations.** The `calibrations` table and `scripts/measure_gate.py
   --write`. Precedence: env var, then calibration row, then default. An
   uncalibrated non-hashing embedder runs with dense rescue OFF.

## Results

### Default (hashing) vs M0 baseline

| Metric | M0 | M3 |
|---|---|---|
| recall@6 | 0.840 | 0.840 |
| gate false-accept (reaches LLM) | 0.188 | **0.175** |
| gate false-accept (confident) | 0.025 | 0.025 |
| gate false-refuse | 0.075 | **0.062** |
| follow-ups answered | 0.467 | **0.944** (17/18) |
| off-topic follow-ups let through | n/a | 0.143 (1/7) |
| search p95 @ 10k / 100k chunks | 285 ms / n.m. | **2.2 ms / 32.9 ms** |

### Semantic embedders (optional install)

| Metric | hashing | bge-small-en-v1.5 | multilingual-e5-small |
|---|---|---|---|
| recall@6 | 0.840 | 0.928 | 0.928 |
| MRR | 0.711 | 0.768 | 0.834 |
| paraphrase recall@6 | 0.700 | 0.900 | 0.900 |
| non-English recall@6 | 0.267 | 0.600 | 0.667 |
| gate false-accept | 0.175 | 0.163 | 0.163 |
| gate false-refuse | 0.062 | 0.062 | 0.062 |

**Target not met:** the roadmap asks for +15 points of recall@6 with a
semantic embedder. Measured: +8.8 (+9.6 with `DENSE_WEIGHT=2`, which is a
one-question difference and not adopted). The ceiling is +16.0, because 80 of
the 125 questions are lexical and already at 1.000. The remaining misses are
non-English questions against English sources (cross-lingual retrieval) and
four paraphrases.

### Why uncalibrated semantic rescue is disabled

With bge-small, off-topic questions reach dense similarity 0.635. At the
hashing-calibrated rescue floor (0.36), 64 of 80 off-topic questions would be
rescued into the borderline band (false accepts 0.963). The measured floor for
bge-small is 0.70 (false accepts 0.163, false refusals 0.050). Rescue
therefore stays off until `measure_gate.py --write` records a floor for the
active embedder.

## Known limitations

- The follow-up detector and its generic-word list were written alongside the
  follow-up dataset (25 conversations), so the 0.944 may be optimistic on new
  data. The one let-through ("And the French president?" against the
  Constitution) passes the raw gate on its own words. It is a gate limitation,
  not a follow-up one.
- Long-context mode is off by default (`LONG_CONTEXT_TOKEN_BUDGET=0`), a
  deliberate deviation from the roadmap's 150k default, because it multiplies
  the prompt cost per answer.
- The cross-encoder reranker is implemented behind its adapter. It was not
  measured here.
