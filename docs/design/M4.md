# M4 — Verifiable citations, persistent chat, streaming

## Citations (C1–C6)

- **Prompt.** Passages keep their `[Source n]` headers, which the v1 tests pin.
  The grounding rules require a `[n]` marker after every sentence that states
  a fact from them (`[1][3]` and `[1, 3]` are accepted). Uncited transitions
  and refusals are allowed.
- **Parser** (`app/core/citations.py`). It extracts markers, removes any that
  point outside 1..k (logged `hallucinated_citation`), and maps each to
  chunk id, source id, offsets, page, slide, timestamp and section. Markers
  written after the period ("… 16. [2] Next") stay with their sentence.
- **Verifier.** support = 0.6 × content-word overlap + 0.4 × embedding cosine,
  computed per (sentence, cited passage). `SUPPORT_FLOOR` = 0.50 is calibrated
  by `scripts/measure_support.py`: supported pairs never score below 0.640
  (including word-dropped restatements), and 5.8% of unrelated pairs reach
  0.50. The floor sits below the supported minimum because real paraphrases
  share fewer words than the test's crude restatements. A citation under the
  floor is `weak`; a sentence whose citations are all weak is `unsupported`.
- **Response.** Cited passages only, in first-marker order, each with a quote
  (the best-matching sentence) for the hover card. Per-retriever ranks move to
  a separate `retrieval` debug list.
- **v1 compatibility.** `/api/chat` keeps `citations`. When the answer has
  markers they are the cited passages; when it has none (older or non-citing
  models, the legacy test stub) they are the passages shown, with
  `citation_mode: "retrieved"`. New fields: `verified_citations`,
  `sentences`, `hallucinated_citations`, `retrieval`.
- **Notes.** Saving a message copies its content (markers included) and its
  verified citations, so the chips stay clickable (C6).

## Chats

Tables `chats`, `messages` and `notes` (migration 003). Chats belong to their
creator: every read is `WHERE user_id = ?`, so other members of a shared
notebook cannot see them. That is enforced in the repository and tested
there; HTTP authentication arrives in M8. History sent to the model is the
last 8 turns of prose. Per-chat source selection and scope persist, and a
message can override them.

## Streaming

`POST /chats/{id}/messages/stream` sends Server-Sent Events: `user_message`,
`decision`, `rewrite` (follow-ups), `retrieval`, `token`…, `citations`,
`done` (the persisted message), or `error`. A refusal is `decision` + `done`
with no LLM call. The response is a hand-rolled `StreamingResponse`, with no
extra dependency.

## Chat configuration and overview

Each notebook's `chat_config_json` holds goal, style (`default`,
`learning_guide` or `custom`), length (`short`, `default` or `long`),
language and name, mapped onto the existing `Persona`. The old presets are
templates (`POST .../chat-config/preset/{key}`), and an imported v1 persona
maps onto the config. The overview job merges the Source Guides (with the LLM
when one is configured, extractively otherwise) and is queued after each guide
and each source deletion. `GET .../overview` reports `stale` when the source
set differs from its snapshot.

## Engine

Generation goes through `app/core/llm.py`. A client injected via
`engine._client` is wrapped in `AnthropicLLM`, so the legacy stubs still work.

## Measured (offline, deterministic answerer)

| Metric | Value | Target |
|---|---|---|
| citation precision | 0.969 | ≥ 0.85 |
| citation recall | 1.000 | ≥ 0.75 |
| unsupported-sentence rate | 0.000 | — |
| hallucinated markers after parsing | 0 by construction | 0 |

The offline "model" quotes passages, so these numbers measure the parser and
verifier, not a real model. A real model's precision and recall need
`python -m eval.run --live`, which costs tokens and has not been run.
