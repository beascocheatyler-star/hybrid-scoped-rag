# M5 — Notebook UI

- **Routes.** `/` is the notebook app (`web/notebook/index.html`). The
  original UI moved to `/classic`, unchanged, so its markdown and scroll
  harnesses keep testing it.
- **Modules** (`web/js/`, `type="module"`, no build step):
  - `api.js`: fetch wrapper, plus an SSE reader over `fetch` (EventSource
    cannot POST).
  - `markdown.js`: the escape-first renderer copied from the classic UI, plus
    renderers for citation chips, answers, citation cards, notes and source
    highlighting.
  - `app.js`: views and state.
  - `studio.js`: the Studio panel (filled in by M6).
- **XSS.** Every `innerHTML` assignment takes the output of a `markdown.js`
  renderer. `tests/notebook_harness.js` (29 checks, under Node and
  JavaScriptCore) feeds hostile titles, quotes, sections, sentences, notes
  and forged markers through each renderer and asserts that only renderer
  tags appear, with no event-handler attributes. Chip attributes contain only
  digits and escaped titles. The viewer highlight escapes each segment
  separately.
- **Answers.** A prose answer is rendered sentence by sentence from the
  server's `sentences`, so unsupported sentences can be wrapped. A
  block-markdown answer is rendered whole, with a count of unverified
  sentences instead.
- **Accessibility.** Landmarks, a skip link, tab/tabpanel semantics with
  arrow keys, aria-labels on icon buttons, `role="log"` with `aria-live` for
  messages, cards on focus, Esc to close, and visible focus rings. Lighthouse:
  accessibility 100 (desktop and mobile) and best practices 100.
- **Tests.** The renderer harness, plus `tests/test_e2e_playwright.py`
  (optional; uses the system Chrome): create a notebook, upload, ask, hover
  the card, click a chip, check the highlighted span, check "Why this
  answer?", check an off-topic refusal, and check the mobile tabs. It fails on
  any console error.
- **Known gaps.** Renaming, notes and new notebooks use `prompt()` dialogs
  (functional and accessible, but plain). There is no drag-and-drop upload.
  The chat config has an API but no UI form yet.
