# M6 — Studio: reports, data tables, mind maps, flashcards, quizzes

## Pipeline (`app/core/studio.py`, one `artifact` job per output)

1. **Gate.** A focus or custom prompt goes through the same deterministic
   scope gate as chat. If it is off-topic, the artifact fails with "outside
   what the selected sources cover" and no LLM call is made (I5).
2. **Passages.** Up to 40 chunks from the **selected sources only** (I1),
   retrieved for the focus or spread round-robin across the sources, and
   numbered `[Source n]` as in chat.
3. **Map.** The existing Source Guides summarise each selected source.
4. **Reduce.** With an LLM: an artifact-specific prompt plus a JSON schema
   (`output_config.format`), with the untrusted-data rule in the system prompt
   (I7). Mind maps are requested as a flat node list, then built into a tree,
   because structured output avoids recursive schemas. Without an LLM, or when
   its output is unusable: deterministic generators built from the passages
   (salient sentences, clozes, guide topics).
5. **Validate.** Pydantic models. Every citation number is mapped to a
   passage, and **items without a valid citation are dropped** (the count is
   reported as `dropped_unsupported_items`). Mind maps are pruned to at most
   80 nodes and depth 4, and padded toward 20 nodes. Quiz answers are checked
   against their options.

Each artifact stores `prompt_used`, its passages, the source-id snapshot it
was generated over, its citations and `generated_by`. Its content never
changes. The `stale` flag compares the snapshot with the current source set:
for "all sources", any addition or removal; for a selection, removal of a
selected source.

## Types

| Type | Params | Output | Exports |
|---|---|---|---|
| report | format (briefing, study_guide, faq, timeline, blog_post, custom), custom_prompt, length, language | sections with `[n]` markers, verified like chat | md, docx, pdf (weasyprint, else printable HTML with `X-Export-Fallback`) |
| data_table | columns or describe | rows of cells, each with citations | csv, citations_csv (row, column, marker, source, page, quote), md |
| mind_map | focus | tree, 20–80 nodes, depth ≤ 4 | svg (server-side), png (client-side canvas), md, json |
| flashcards | quantity (10/20/40), difficulty, focus | front, back, citations | md, json |
| quiz | quantity, difficulty, types ⊂ {multiple_choice, multi_select, short_answer, fill_blank} | question, options, answer, rationale, citations | md, json |

Grading: multiple choice, multi-select and fill-in are graded exactly. Short
answers are graded by `MODEL_JUDGE` against the cited passage and the model
answer, or by lexical overlap of at least 0.5 without an LLM. Every graded
attempt and flashcard mark is stored per user in `study_progress`, with
"retake all" and "retake missed" support.

Notebook copy now carries ready artifacts, with source and chunk ids remapped
to the copies.

## UI (`web/js/studio.js`)

Generator cards, then a customise dialog, then a job, then the viewer opens
automatically. Report: markdown with chips. Table: escaped table with per-cell
chips. Flashcards: flip (click/Space/Enter), Got it/Missed it, a progress
counter, Explain (asks the chat), and retake all/missed. Quiz: per-item Check,
then rationale with chips, then a running score and "Ask the chat about my
weak areas". Mind map: SVG built with `textContent` only. Click the circle to
collapse or expand; click the label (or press Enter) to ask "Tell me about
<label>" in the chat with the same source selection. Wheel/drag or the +/−
buttons zoom and pan; PNG export uses a canvas.

## Honest limitations

- Deterministic (no-LLM) flashcards and quizzes are clozes and template
  questions. They are correct and cited, but plainer than LLM output, and
  their distractors can be weak. They exist so the feature works offline and
  so tests have no external dependency.
- PDF export needs `weasyprint`; without it the endpoint returns printable
  HTML and says so in a header.
- The LLM path is tested with a fake model only (schema, prompt, citation
  validation, item dropping); output quality with a real model is unmeasured.
